Software factory research plan

Generic roles and how our fleet fills them

A research question is written in the generic role (left column), so it can be asked of any software factory. Its grounding names how this fleet fills that role (right column) and which records answer it here.

generic role what it is in any factory our instance (the fleet at ~/workspaces/aihero)
factory people, agents, harness and repos run as one production system this fleet, run by one person
factory owner the person who sets the factory's rules and starts its work you
fleet the set of repos the factory is responsible for FLEET.md groups template, apps, infra
fleet map the record of which repos are in the fleet and how they relate FLEET.md
template repo the repo new products are cloned from hero-template
clone a product repo started from the template elevate-commons, ah-cozy, aihero-wayfare, aihero-mehr, aihero-dokyu, aihero-steadfast
shared service a repo other products depend on at runtime auth (the identity provider)
design system the shared UI component source and its registry design-system
design source where product design is authored before code the claude.ai Design projects and aihero-*-design exports
infrastructure repos code that provisions and deploys the fleet infrastructure-root, infrastructure-environments
process plugin the packaged instructions and scripts the agents follow the wayfare-skills plugin (formerly hero-skills)
skill one packaged procedure in the process plugin wayfare:wayfare-*
vendored asset a file copied from the process plugin into each repo hooks, rules, the auto-approve caller workflow
harness the agent runtime Claude Code, its models, limits and settings
agent session one run of the harness a Claude Code session transcript
subagent an agent a session delegates to Claude Code subagents
work-item store where work is planned and tracked, per repo .plans/ (goals, items, logs)
work item one planned unit of work a .plans item
found work work an agent discovered while doing other work items with a discovered_from
cross-repo message a request one repo's agent leaves for another's .plans outbox / inbox signals
design record the repo's statement of its architecture and decisions DESIGN.md
agent instructions the standing instructions agents load AGENTS.md / CLAUDE.md, .claude/rules/
agent memory facts an agent saves across sessions Claude Code memory files
control register the fleet-wide list of controls and checks .fleet/CONTROLS.yaml, CHECKS.yaml, CONSISTENCY.md
gate a point where work stops until something passes CI checks, self-review, ready-mark, "go", auto-approve
judge an automated reviewer that approves or rejects the auto-approve workflow
human gates the points where the owner must act marking a plan ready, saying "go"
sweep one change applied across many repos a fleet sweep via wayfare-sync-*
upkeep work that keeps the fleet current rather than adding features dependency bumps, re-vendoring, compliance fixes
spend what running the agents costs Claude Code cost (API-equivalent), plan and limits, CI minutes

Rules for writing a generic question: - No repo, PR, item, file, skill or model name in generic_question. Those go in grounding. - Use the generic role names above. If a question needs a role that isn't here, add a row rather than using our name. - A question that only makes sense for this fleet (e.g. about one repo's rename) is kept only as an instance under a generic question it illustrates.
